# 在线房间游戏

一个自部署、邀请制、三人在线房间游戏。玩家通过房间码加入，系统临时保存房间状态、昵称和浏览器本地重连令牌；结算后或房间清理后不保留服务端对局历史。

## 项目宪章要点

项目变更必须遵守 `.specify/memory/constitution.md`：服务端权威处理规则和结算、仅保留临时房间数据、测试先行、保持单体自托管 TypeScript 架构，并默认使用中文处理玩家文案和非专业说明。

## 功能

- 创建房间、分享房间码、三名玩家加入
- 浏览器本地重连令牌取回原席位
- 服务端权威的身份发牌、阶段推进、计时、投票和结算
- 限时阶段使用服务端时间校准，浏览器每秒连续显示倒计时；断线重连不会重启阶段倒计时
- 每局使用服务端新随机洗牌分配身份；同一局内刷新或重连保持原初始身份
- 狼人、预言家、强盗、捣蛋鬼、水鬼、平民六张身份牌规则
- 私密身份行动结果与结算时全量揭示
- 自由发言文字聊天，仅实时转发，不保存聊天记录
- 极简文字/CSS UI，无自定义美术

## 环境要求

- Node.js 20+
- npm
- 现代浏览器

## 本地开发

```bash
npm install
npm run dev
```

默认访问：`http://localhost:3000`

## 测试与构建

```bash
npm test          # Vitest 单元 + 集成测试
npm run test:e2e  # Playwright 三浏览器流程测试
npm run build     # 构建前端与服务端
npm start         # 运行构建后的自托管服务
```

首次运行 Playwright 如缺少浏览器，请执行：

```bash
npx playwright install chromium
```

## 配置

复制 `.env.example` 并按需设置：

```bash
PORT=3000
PUBLIC_ORIGIN=http://localhost:3000
ROOM_IDLE_TTL_MS=1800000
PHASE_TIME_SCALE=1
VOTING_TIMEOUT_MS=60000
```

公开部署时，必须将服务放在 HTTPS 反向代理之后或等效加密传输环境中，确保重连令牌和私密身份事件在传输中加密。

## 手动冒烟流程

1. 打开三个浏览器窗口或三个独立浏览器上下文。
2. 第一个玩家创建房间并复制房间码。
3. 另外两名玩家使用房间码和不同昵称加入。
4. 房主开始游戏。
5. 观察“闭眼准备”和身份行动阶段：倒计时应每秒递减，不冻结、不跳回，玩家行动后也不重置。
6. 游戏中刷新一个玩家页面，用房间码重连并确认回到原席位；倒计时应与其他玩家相差不超过约 2 秒，初始身份保持不变。
7. 等待或执行身份行动；必选身份超时会自动选择有效目标，非行动玩家只看到中文等待提示。
8. 进入自由发言并发送文字消息；自由发言不显示自动结束倒计时。
9. 房主推进到投票，确认显示投票进度；三名玩家各投一票，或等待投票超时自动结算。
10. 查看投票、出局结果、胜利阵营、最终身份和最终水下牌。
11. 连续创建几局新房间并用相同昵称/加入顺序开始游戏，身份不应固定到同一玩家；自然随机偶发重复属于正常情况。

### 排查提示

- 如果倒计时卡住，先确认浏览器已收到 `state:public` 且包含 `serverNow`、`phaseStartedAt` 和限时阶段的 `phaseEndsAt`。
- 如果重连后时间从阶段开头重新开始，检查 Socket.IO 重连是否使用原房间码和本地重连令牌，服务端不应重新发牌或重新设置阶段时间。
- 如果多局身份看起来固定，确认生产开局没有传入测试 `seed`，并检查服务端日志中是否复用了同一个活动房间状态。

## 隐私与数据保留

- 不包含用户账户、公开大厅、匹配、全局资料或社区功能。
- 服务端只在内存中保存临时昵称、房间/对局状态、重连令牌哈希和活跃聊天转发数据。
- 聊天消息不写入服务端历史记录。
- 房间清理后不保留服务端对局历史。
