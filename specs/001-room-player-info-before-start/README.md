# 开局前房间人员信息展示

> **Status**: complete · **Priority**: medium · **Created**: 2026-05-24

## Overview

玩家创建或加入房间后，在房主开始游戏前，应能清楚看到当前房间内已有人员信息，避免玩家不知道谁已进入、是否满员、谁可以开始游戏。

本规格只覆盖等待开局状态下的公开人员信息展示，不改变发牌、身份可见性、行动流程或结算规则。

## Goals

- 进入房间后立即展示当前人员列表和房间容量进度。
- 当其他玩家加入、离线、重连或离开等待房间时，所有房间成员无需刷新即可看到更新。
- 明确标识本人、房主、在线/离线状态，以及是否已满足开局条件。
- 开局前不展示任何身份牌、阵营、水下牌或可能泄露对局随机结果的信息。

## Non-goals

- 不新增公开大厅、匹配、踢人、准备按钮或聊天功能。
- 不改变房间最大人数、开始游戏权限或断线重连规则。
- 不要求记录历史人员信息；房间关闭后仍按临时房间策略清理。

## User Scenarios

### User Story 1 - 玩家进入房间后确认当前人员

作为已进入房间的玩家，我希望在等待开局时看到当前有哪些玩家已经加入，以便确认朋友是否进对房间、是否还缺人。

Acceptance scenarios:

1. **Given** 玩家创建房间成功，**When** 等待开局界面显示，**Then** 玩家看到当前人员为 1/3，列表中包含自己的昵称，并标识“你”和“房主”。
2. **Given** 房间处于等待开局且已有玩家，**When** 新玩家加入成功，**Then** 所有在线成员看到人员列表更新为最新人数和昵称。
3. **Given** 房间人数未满三人，**When** 玩家查看开局区域，**Then** 界面提示还需多少人加入，开始游戏按钮不可用或不显示为可点击状态。
4. **Given** 房间已满三名在线玩家，**When** 房主查看等待开局界面，**Then** 界面显示 3/3 且房主可以开始游戏；非房主看到“等待房主开始游戏”的提示。

### User Story 2 - 玩家理解连接状态变化

作为等待开局的玩家，我希望看到成员在线或离线状态，以便知道是否需要等待某人重连后再开局。

Acceptance scenarios:

1. **Given** 等待开局时某玩家断线，**When** 房间状态同步，**Then** 其他成员看到该玩家标记为“离线”。
2. **Given** 离线玩家通过有效重连回到原席位，**When** 重连成功，**Then** 人员列表保留其原昵称和席位，并更新为“在线”。
3. **Given** 房间存在离线成员，**When** 房主查看开始游戏按钮，**Then** 开始游戏不可用，并显示需要所有成员在线的原因。

## Requirements

- **FR-001**: 系统 MUST 在房间处于等待开局状态时展示人员信息面板。
- **FR-002**: 人员信息面板 MUST 显示已占用席位的昵称、席位序号、房主标识、本人标识和连接状态。
- **FR-003**: 人员信息面板 MUST 显示容量进度，例如“当前人员 2/3”，并在未满员时说明还需加入的人数。
- **FR-004**: 人员列表 MUST 基于服务端权威房间状态渲染；客户端不得自行推断或伪造其他玩家信息。
- **FR-005**: 玩家加入、断线、重连或离开等待房间后，系统 MUST 向房间内在线成员同步最新人员信息，目标是在 2 秒内可见。
- **FR-006**: 开局前人员信息 MUST 只包含公开信息，不得展示身份牌、阵营、水下牌、行动资格或任何随机发牌结果。
- **FR-007**: 当房间未满三名在线玩家时，系统 MUST 明确提示不能开始游戏的原因。
- **FR-008**: 当房间已有三名在线玩家时，系统 MUST 仅允许房主开始游戏；非房主 MUST 看到等待房主开始游戏的提示。
- **FR-009**: 人员信息展示 SHOULD 在桌面端和移动端保持可读，避免占用过多纵向空间。

- 等待房间新增 3 个固定席位渲染，空席位显示“等待加入”；开始游戏提示区统一说明缺人数、离线阻塞、房主可开局或非房主等待。
